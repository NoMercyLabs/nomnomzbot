# Benchmark: page layouts (frame, scrolling, tabs, panes)

Method: every row comes from page text read on 2026-10-12 in a real browser (Chrome DevTools MCP, page text of the rendered page), and every row keeps the URL that was opened. Plain WebFetch returned an error page for Twitch help and 404 for two guessed URLs, so those sources were read in the browser. Where a page states no scroll behaviour, the row says what the page states and nothing more. Vercel and Discord pages are help articles; their rows state only the navigation facts the article text gives. Ours says what the 2026-10-12 layout mockups (.scratch/layout-mockups) do with each row; Status "missing" means the app does not have it and no mockup shows it. Goal behind the research: 4 or 5 page layouts for the 57 dashboard pages, a full-height frame where panels scroll and the page never scrolls, and at most one tab row per page.

## Notes for the layout design (facts only)

- Not checked in any source: which element scrolls (page or panel) on Linear, Vercel, GitHub, Discord and StreamElements. The pages read describe regions, not scroll containers. Only the shadcn sidebar page states a scroll region (SidebarContent scrolls between a sticky header and footer). Check live apps before the layout mockups claim a pattern for scroll behaviour.
- Not checked: Streamlabs. StreamElements was used for the bot-dashboard row set.
- Vercel and Discord rows are thin on layout: their help articles describe navigation, not page frames.
