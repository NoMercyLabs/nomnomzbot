# EventSub test fixtures vs the Twitch docs

12 match, 63 fixed (every field the docs list now present), 1 open: ad break int/bool types need a live capture. One fixed line keeps a type note (automod message dict vs doc string) that is not an added field (of 76 fixtures).

Source of the fixtures: `server/src/NomNomzBot.Infrastructure/DevPlatform/EventSamplePayloads.cs` (dictionary `ByWireName`).
Source of the docs: the Twitch EventSub subscription types page, notification examples, fetched 2026-10-07.

Method: every fixture is matched by subscription type and version to a doc notification example. Each JSON path in the doc example is compared with the fixture. When a type has several doc examples (for example one per action), the doc example with the most overlap is the base for "missing", and the union of all its examples is the base for "extra".

How to read a line: `wire name` | Twitch subscription type | version | status | doc anchor.

- `missing` = path in the doc example but not in the fixture. Many are `null` in the doc (for example `cheermote`, `emote`, `reply`) and only appear in some message kinds.
- `extra` = path in the fixture but not in any doc example for that version. Not always wrong: some doc examples show only one variant.
- `type` = same path, different JSON type. The doc example for ad break shows numbers and booleans as strings. The doc example is the only source checked; whether Twitch sends strings on the wire is not checked, so this needs a live capture before any change.
- Path syntax: `a/b` is nested object key, `a[]/b` is a key inside an array element.
- Doc matches: 76 of 76 fixtures have a doc example (subscription type and version). No fixture is without one.
